# Meticulous

> Meticulous records real user sessions from a web app and replays them against
> each commit to catch visual regressions. Results are visual diffs: pairs of
> screenshots plus DOM, network and timeline data for each replay.

## Project setup

To integrate Meticulous into a repository, follow the [Project setup guide](https://app.meticulous.ai/docs/project-setup.md).
It covers recorder installation, skills and MCP, CI configuration, and verification.

## Accessing Meticulous results from a coding agent

Meticulous results show how a code change actually affects the UI. Check them
when reviewing a pull request, after pushing frontend changes, before calling a
pull request done, and whenever the Meticulous CI check fails or is pending.

The web app at https://app.meticulous.ai needs a browser login and presents
results as images, so it isn't agent-friendly. Use the CLI or MCP instead — they
expose the same test runs, diffs and screenshots as text and downloadable files.
Links to the web app still carry the IDs to pass them, e.g.
`/projects/<organization>/<project>/test-runs/<testRunId>`.

This section is for reading and reviewing results after project setup; it is not
the guide for installing Meticulous into an application.

CLI / MCP / skills instructions: https://app.meticulous.ai/docs/agents/setup-for-agents.md

Quick start:

- MCP server: https://app.meticulous.ai/api/mcp (if one is already connected, use it)
- CLI: `npm install --global @alwaysmeticulous/cli@latest`, then
  `meticulous auth login --non-interactive` (or `meticulous auth login --device`
  on a remote or sandboxed machine). `meticulous agent --help` explains when and
  how to use the commands.
- Skills (pre-written workflows, including `meticulous-review` and
  `meticulous-fix`): `npx skills add alwaysmeticulous/skills --skill "*" --agent claude-code --agent codex --agent cursor -y`

Without the skills, start from the diffs with their review state
(`meticulous agent test-run-diffs --includeReviews`, or MCP
`get_test_run_diffs` with `includeReviews`). Investigate unreviewed diffs —
images, DOM diff, timeline — before rejecting, ignoring or approving them; for
rejected or commented diffs, fix the issue and reply on the thread.
